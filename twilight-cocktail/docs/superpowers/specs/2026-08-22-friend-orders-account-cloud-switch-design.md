# 朋友点单与账号云端切换设计

日期：2026-08-22  
状态：已确认方案 A，待实现

## 目标

本次改动解决四类关联问题：

1. 朋友点单过多时占用页面空间，增加与“我的作品”一致的折叠交互。
2. 保证单条点单删除后刷新不会恢复，并补齐端到端回归验证。
3. 关闭朋友点单链接时，在确认后同时使链接失效并删除该链接下全部点单。
4. 登录或切换云端账号时以目标账号云端数据为准，覆盖完整本地账号数据包，避免账号之间串数据。
5. 新增带照片作品时，区分“本地保存”和“云端备份”结果，避免临时网络失败被错误显示为作品保存失败。

## 设计原则

- 云端是已登录账号的数据真源，本地只作为当前账号的活动副本和照片缓存。
- 不合并不同账号的数据，也不把上一账号的本地内容自动上传到新账号。
- 任何破坏性替换都必须先完成目标账号验证和云端读取，再向用户确认。
- 云端读取失败、密码错误或用户取消时，不改变当前账号和本地数据。
- 照片云备份失败不否定已经成功的本地作品保存；待上传照片必须留在本地队列中供重试。

## 一、账号切换与云端覆盖

### 数据范围

切换账号时替换整个账号数据包：

- 作品文字与照片元数据
- 本地原图、预览图缓存
- 酒柜材料
- 收藏
- 课程进度
- 每日推荐
- 自定义鸡尾酒、自定义调味酒和自定义饮料
- 自动备份开关及最后备份时间
- 本地作品删除记录和同步游标

制作模式的临时步骤、设备匿名标识等不属于账号备份数据，不纳入本次迁移。

### 两阶段切换流程

1. 用户输入目标账号和密码。
2. 客户端计算账号身份并调用云函数验证，但暂不保存为当前会话。
3. 已存在账号：把完整云端数据读取到内存中的暂存对象。
4. 不存在账号：暂不创建，先把目标状态标记为“新空账号”。
5. 页面弹出确认窗口，显示当前本地作品数量和目标云端作品数量：
   - 已有云端数据：说明继续后完整覆盖本地账号数据。
   - 新账号或空云端：说明继续后本地账号数据将被清空。
6. 用户取消：丢弃暂存结果，当前会话和本地数据不变。
7. 用户确认：
   - 新账号此时才创建；
   - 保存目标账号会话；
   - 用暂存的完整云端数据统一替换本地状态；
   - 清空上一账号的照片 IndexedDB 缓存、删除记录和同步状态；
   - 清空页面中上一账号的朋友点单和分享链接状态；
   - 加载目标账号的点单链接与订单；
   - 自动恢复目标账号全部作品预览图。

### 失败处理

- 验证或读取失败：保留原会话和全部本地数据。
- 本地数据写入失败：恢复切换前的本地快照，并保持原会话。
- 预览图恢复失败：账号文字数据仍切换成功，界面显示失败数量并保留“继续/重试”入口。
- 同一账号重新登录也会检查云端，但只有用户确认后才覆盖本地数据。

## 二、朋友点单折叠

- 点单区域默认只显示摘要栏：“当前有 N 条朋友点单”。
- 摘要栏提供展开/收回箭头，交互和“我的作品”保持一致。
- 点单卡片只在展开时渲染，刷新页面后默认保持收起。
- 新点单提醒中的“查看”会关闭提醒、展开点单列表并滚动到点单区域。
- 删除到零条时显示空状态，摘要栏仍保留，方便手动刷新。

## 三、点单删除与关闭链接

### 单条删除

- 客户端调用 `drink-request-delete`，仅在服务端确认成功后移除本地卡片。
- 服务端持久化过滤后的完整 `drinkRequests` 和准确的 `drinkRequestCount`。
- 增加“删除后重新获取仍不存在”的云函数测试、页面测试和部署后接口验证。
- 删除失败时保留卡片并显示错误，不做假删除。

### 关闭链接并删除全部点单

关闭按钮先弹出确认：

> 关闭后当前链接立即失效，并永久删除该链接下全部 N 条点单，是否继续？

用户确认后：

1. 账号文档先写入 `requestShareEnabled: false`、空点单数组和数量零。
2. 再禁用分享链接文档。
3. 前端收到成功结果后清空链接、点单列表和已读数量。

提交点单时本来就会同时校验账号分享状态和链接文档，因此账号文档先关闭可以保证即使第二步短暂失败，旧链接也无法继续新增点单。

“重置链接”只轮换链接，不删除历史点单；只有“关闭链接”执行全量删除。

## 四、作品保存与照片云备份

### 已确认的问题路径

当前新增带照片作品时：

1. 作品先写入本地。
2. `attachPreparedPhoto` 立即上传照片。
3. 页面随后再次调用整包云端备份。
4. 任一云端请求发生临时网络错误，统一显示“保存失败”。

线上云函数和 CORS 当前可访问，手动备份可以成功，说明本地保存及云端配置有效；问题集中在即时上传链路缺少结果分层和可靠重试。

### 调整方案

- `attachPreparedPhoto` 只负责把原图和预览图可靠写入 IndexedDB，并把作品标记为待上传。
- 页面只调用一次统一备份流程：先上传所有待处理照片，再同步作品及账号元数据。
- 对无副作用的照片签名准备请求和幂等元数据同步，在网络连接异常时安全重试一次；不对创建链接、提交点单等非幂等动作做通用重试。
- 本地作品及照片缓存成功后，保存结果视为成功。
- 云端同步成功：提示“作品已保存并完成云备份”。
- 云端同步仍失败：提示“作品已保存到本机，云备份待重试”，保留失败原因和手动备份入口，不再显示“保存失败”。
- 手动“备份到云端”继续处理全部待上传照片；上传成功后更新照片对象键和元数据。

## 五、测试与验收

### 前端测试

- 点单默认折叠、展开和收回。
- 新点单“查看”自动展开。
- 单条删除成功和失败状态。
- 关闭链接确认、取消，以及成功后清空点单。
- 账号验证失败、用户取消时本地数据不变。
- 已有账号云端数据整体覆盖全部本地账号数据。
- 新空账号确认后清空全部本地账号数据。
- 照片缓存和账号会话在确认前不切换。
- 预览图恢复失败可重试。
- 云备份失败时作品仍保存、照片保持待上传，提示不再使用“保存失败”。

### 云函数测试

- 单条点单删除后再次读取不存在。
- 关闭分享链接后点单数组为空、数量为零、旧链接无法提交。
- 新账号在确认前不会被创建。
- 账号读取接口返回完整账号数据包和作品数量。

### 部署验收

- 运行云函数和前端全量测试、类型检查与生产构建。
- 部署实际 HTTP 路由对应的 CloudBase 函数。
- 发布 GitHub Pages。
- 在线验证点单折叠、删除持久化、关闭链接全量删除、两个测试账号切换、空账号覆盖、照片待重试和手动备份恢复。
