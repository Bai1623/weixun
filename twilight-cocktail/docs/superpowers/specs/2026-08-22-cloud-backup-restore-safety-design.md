# 云端备份与恢复安全体验设计

日期：2026-08-22  
状态：用户已确认实施全部 P0 项

## 目标

把当前“操作后才显示结果”的云端功能升级为可持续感知的账号备份状态，并保证恢复和多设备上传不会在用户不知情时覆盖数据。

本次 P0 范围包括：

1. 登录账号后每次打开作品页自动检查云端，并提供手动重新检查按钮。
2. 展示云端最后备份时间、各类账号数据数量以及照片预览图/原图完整度。
3. 从云端恢复前先展示本地与云端数据概况，再由用户确认完整覆盖。
4. 覆盖确认基于完整账号数据包，不能只判断本地作品数量。
5. 每次上传前重新检查云端版本；检测到另一设备产生的新版本时阻止无提示覆盖。
6. 恢复前创建一个同账号本地恢复点，并在恢复后提供一次撤销入口。

## 设计原则

- 云端是已登录账号的数据真源；页面展示必须来自实时云端查询，不能用本次浏览器会话的操作状态冒充云端状态。
- “检查云端”“备份到云端”“从云端恢复”是三个独立动作，文案和状态不能混用。
- 任何完整覆盖都必须先下载和验证远端数据、展示范围、创建本地恢复点，再修改本地状态。
- 多设备版本不一致时默认阻止上传，不提供静默的“最后写入覆盖”。
- 照片二进制继续保存在私有 OSS 和本地 IndexedDB；CloudBase 摘要只包含数量、时间和对象元数据，不下载照片文件。
- 保持现有 Vue、Pinia、CloudBase、OSS 和页面风格，不引入新的运行时依赖，不做无关页面重构。

## 一、云端快照摘要

### 云函数契约

新增只读动作 `account-summary`。验证当前账号后返回：

- `snapshotId`：本次云端账号数据版本，使用账号文档的 `metadataUpdatedAt` 或 `backupCreatedAt`。
- `backupCreatedAt`：服务端最后成功保存账号数据的时间。
- `dataLastBackupAt`：账号数据包内的最后备份时间，用于识别本机是否基于同一云端版本。
- `summary`：作品、预览图、原图、酒柜、收藏、课程进度、每日推荐、自定义鸡尾酒、自定义调味酒和自定义饮料的数量。

旧版分片备份仍兼容：云函数在服务端读取旧分片并生成摘要，客户端不下载整包数据。新接口不返回 OSS 地址、密码校验值或照片内容。

### 前端状态

新增独立的 `cloudSnapshot` 状态，不复用现有 `cloudSync` 操作状态。状态包括：

- `idle`：未登录或尚未检查。
- `checking`：正在查询云端。
- `ready`：已取得快照。
- `error`：查询失败，保留最后一次成功快照并标记可能过期。

快照同时记录 `checkedAt`、账号名、版本、备份时间、分类数量和本机关系：

- `empty`：云端没有账号数据。
- `same-base`：云端数据包的最后备份标记与本机一致。
- `cloud-changed`：云端已被其他设备或会话更新。
- `unknown-base`：云端有数据，但本机没有可验证的备份基线。

页面加载、账号激活和手动点击“重新检查”都会调用摘要接口。查询失败只影响状态展示，不删除本地数据。

## 二、上传前版本保护

每次手动或自动备份前都重新调用 `account-summary`：

1. 云端为空时允许上传。
2. 云端 `dataLastBackupAt` 与本机 `autoBackup.lastBackupAt` 一致时允许上传。
3. 云端有数据且版本标记不同或本机没有基线时，中止上传并显示冲突提示，引导用户先查看云端恢复预览。
4. 上传成功后使用 `metadata-patch` 返回的 `metadataUpdatedAt` 更新云端快照，同时把新的 `lastBackupAt` 写回本机。

本次不实现逐字段双向合并。作品、酒柜、收藏等账号数据仍按现有整包语义处理；P0 的目标是防止无提示覆盖。

## 三、恢复前预览

点击“从云端恢复”后先完整读取并规范化云端账号数据，但暂不修改本地：

1. 生成本地账号摘要和云端账号摘要。
2. 展示云端快照时间和本地/云端两列数量。
3. 单独展示作品总数、带预览图数和带原图数。
4. 明确说明恢复会覆盖作品和照片元数据、酒柜、收藏、课程、每日推荐、自定义材料和自动备份设置。
5. 无论本地作品是否为零，只要用户点击恢复，都必须在专用弹窗中确认。

恢复确认不再使用浏览器原生 `window.confirm`。如果用户查看预览后云端版本再次变化，确认时终止操作并要求重新检查，避免恢复一个已经过期的暂存数据包。

## 四、本地恢复点与撤销

确认恢复后、写入云端数据前，保存同账号的一次性本地恢复点：

- 完整本地账号元数据包。
- 本地删除记录。
- 自动备份状态和本地同步游标。
- 创建时间和账号标识。

恢复点中的作品不重复保存已经迁移到 IndexedDB / OSS 的照片 Data URL；只有尚未迁移、且没有 `photoRevision` 的旧版作品保留其唯一一份 Data URL，避免撤销时永久丢图。原图和预览图仍留在 IndexedDB，撤销时根据作品 ID 重新关联。恢复成功后云端状态卡显示“撤销本次恢复”。撤销只允许在相同云端账号下执行，成功后删除该恢复点；新一次恢复会覆盖旧恢复点。

如果本地写入失败，立即使用内存快照回滚，不显示成功状态。照片预览恢复失败不回滚已经恢复的账号元数据，但保留原有“继续/重试”和“撤销本次恢复”入口。

## 五、页面结构与反馈

作品页的云端区域按以下层级显示：

1. 当前云端账号。
2. 云端备份摘要卡：状态、最后备份、最后检查、重新检查。
3. 数据数量和照片完整度。
4. 自动备份和朋友点单。
5. 备份、恢复、导入导出操作。
6. 最近一次操作结果。

“云端状态”不再显示“尚未同步云端”这类无法代表远端事实的默认文案。未查询时显示“尚未检查云端”，查询失败显示失败原因和最后成功检查时间。

## 六、测试与部署验收

### 云函数

- `account-summary` 返回正确版本时间和所有分类数量。
- 旧版分片账号可以生成相同摘要。
- 密码错误和不存在账号不会泄露摘要。

### 前端服务与 Store

- 页面加载自动查询，手动查询可重试。
- 云端有数据时刷新后显示真实数量。
- 上传前云端版本变化会阻止上传，版本一致允许上传。
- 恢复预览不修改本地数据。
- 本地只有酒柜、收藏或课程数据时仍要求确认。
- 恢复成功后可撤销；账号不匹配时不能使用恢复点。
- 云端在预览和确认之间变化时停止恢复。

### 页面

- 云端摘要、检查时间、备份时间和照片完整度可见。
- 恢复弹窗展示本地/云端完整范围，取消不修改数据。
- 操作中、失败、冲突和成功反馈明确。

### 部署

- 运行云函数测试、前端全量测试、类型检查、生产构建和 `git diff --check`。
- 部署 `twilightWorks` 实际 HTTP 路由所使用的 CloudBase 函数。
- 发布 GitHub Pages，并在线验证自动检查、手动检查、恢复预览和冲突保护。
