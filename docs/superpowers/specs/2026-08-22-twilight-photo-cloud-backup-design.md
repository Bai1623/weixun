# 暮调鸡尾酒照片云备份设计

日期：2026-08-22
状态：已由用户确认设计，待制定实施计划

## 背景

暮调鸡尾酒目前把作品照片压缩为最长边 1280px、JPEG 质量 0.82 的 Base64 字符串，并保存在浏览器 `localStorage`。现有腾讯 CloudBase 同步只同步作品及应用元数据，明确清空 `photoDataUrl`，因此换电脑后无法恢复照片。

项目已经使用腾讯 CloudBase HTTP 云函数 `/share` 和数据库集合 `bai` 保存账号数据。本次新增阿里云 OSS 作为私有照片存储，Bucket 为 `twilight-cocktail-bai`，Region 为 `oss-cn-hangzhou`。阿里云侧已经创建专用 RAM 用户、AccessKey、CORS 规则和仅允许访问 `photos/*` 的最小权限策略。

## 目标

- 新作品同时备份手机原图和适合界面展示的压缩预览图。
- 新电脑登录云端账号后自动恢复全部作品和全部预览图。
- 原图保存在 OSS，需要时单独下载，不在登录时批量下载。
- 保持 Bucket 私有，任何阿里云永久凭证都不进入浏览器、数据库、日志或 Git 仓库。
- 支持上传失败重试、照片替换、作品删除和旧数据兼容。
- 避免大量 Base64 图片撑爆 `localStorage`。

## 非目标

- 不尝试还原旧作品已经丢失的手机原图。
- 第一版不提供相册多图、视频、Live Photo 双文件或 RAW 专用处理流程。
- 不引入公开读 Bucket、CDN、图片处理服务或跨区域复制。
- 不重做现有暮调账号体系；照片接口继续使用现有 `accountNameKey` 和 `passwordVerifier` 校验。
- 不自动把全部原图下载到新电脑。

## 已确认的产品决策

1. 每个新作品保存两份文件：原图和预览图。
2. 预览图沿用现有规格：最长边 1280px、JPEG 质量 0.82。
3. 单张原图上限为 50 MB，只接受图片文件。
4. 新电脑登录成功后自动下载全部预览图，并显示总进度。
5. 原图只在用户主动点击“下载原图”时下载。
6. 旧作品只能把现存压缩图迁移为预览图，并显示“仅有预览图”。

## 总体架构

### 前端

前端在用户选择照片后先把原始 `File` 写入 IndexedDB，再生成并写入 JPEG 预览 Blob。预览图作为长期本机缓存，原图作为上传成功前的待同步数据。上传完成并确认云端元数据已经保存后，可以移除本机待上传原图；预览图继续缓存供离线展示。若浏览器无法生成预览，原始文件仍保留在待处理区，作品文字仍可保存。

现有作品文字元数据继续使用 Pinia 和 `localStorage`。新增一个职责单一的照片缓存服务管理 IndexedDB，不把 Blob 混入作品 JSON。运行时由作品 Store 维护 `workId -> object URL` 映射，页面通过统一方法取得展示地址。旧记录的 `photoDataUrl` 在完成迁移前仍然可读。

### 腾讯 CloudBase 云函数

现有 `/share` 云函数继续作为唯一受信任服务端，新增照片相关 action：

- `photo-upload-prepare`：验证账号、作品 ID、文件类型和大小，由服务端生成对象路径和短期 PUT 预签名 URL。
- `photo-download-prepare`：验证账号并从该账号已保存的作品元数据中取得 Object Key，生成短期 GET 预签名 URL；客户端不能传任意路径换取下载地址。
- 现有 `metadata-patch`：接受照片元数据时校验路径必须属于当前账号，并通过 HeadObject 确认相应文件已经存在，再写入数据库。
- 照片清理：`metadata-patch` 在作品删除或照片版本替换时记录旧 Object Key，数据库更新成功后再删除旧文件。删除失败的 Key 进入账号文档中的清理队列，在后续认证请求中重试。

云函数使用 `ali-oss` Node.js SDK。永久 AccessKey 只从云函数环境变量读取。

### 阿里云 OSS

Bucket 始终保持私有。浏览器只获得短期、限定 HTTP 方法和具体 Object Key 的签名 URL。对象路径由云函数生成，不信任客户端提供的完整路径。

对象路径格式：

```text
photos/{accountNameKey}/{workId}/{photoRevision}/original.{ext}
photos/{accountNameKey}/{workId}/{photoRevision}/preview.jpg
```

`photoRevision` 每次新增或替换照片时生成。新版本写入并验证成功前不删除旧版本。

## 数据模型

在现有 `WorkRecord` 上增加可选字段，以兼容旧 JSON：

```text
photoOriginalObjectKey
photoPreviewObjectKey
photoOriginalName
photoOriginalMime
photoOriginalSize
photoRevision
photoBackupMode: none | preview-only | original-and-preview
```

`photoDataUrl` 暂时保留为旧数据兼容字段。新记录不再长期依赖该字段保存照片。同步状态（待备份、上传中、失败）属于本机运行状态，存入照片缓存/同步队列，不作为跨设备的作品业务字段；云端 Object Key 是否齐全决定“已备份”或“仅有预览图”。

数据库只保存 Object Key 和必要元数据，不保存预签名 URL、Base64 照片或阿里云凭证。

## 关键流程

### 新建作品

1. 校验图片类型和 50 MB 大小上限。
2. 创建照片版本，把原图写入 IndexedDB。
3. 生成预览 Blob 并写入 IndexedDB；若生成失败，则记录可重试错误。
4. 保存本地作品，状态为“待备份”或“失败可重试”，离线和预览失败都不丢文字记录与原文件。
5. 登录、在线且两份 Blob 就绪时请求 `photo-upload-prepare`。
6. 浏览器使用两个签名 PUT URL 直传 OSS。
7. 两份文件都成功后，通过 `metadata-patch` 保存照片 Object Key。
8. 云函数 HeadObject 校验文件存在且路径属于当前账号，然后更新数据库。
9. 前端标记“已备份”，移除待上传原图，保留预览缓存。

### 上传重试

Object Key 由账号、作品、版本确定，同一版本重试时保持不变。若只上传成功一份，重试会覆盖或补齐同一路径，不创建无限重复文件。只有两份均存在时，新作品才标记为“原图和预览图已备份”。单条失败不阻塞其他作品。

### 新电脑登录和全量恢复

1. 先使用现有流程恢复全部作品文字元数据。
2. 收集所有具有 `photoPreviewObjectKey` 且本机 IndexedDB 未命中的作品。
3. 分批向云函数请求这些作品的预览图签名 URL。
4. 以受控并发下载全部预览图并写入 IndexedDB。
5. 显示总体进度，例如“正在恢复照片 38/126”。
6. 单张失败不终止全局任务，结束后显示失败数量并提供“重试失败项”。
7. 用户可以暂停和继续；已缓存且版本一致的照片不重复下载。

登录恢复不自动下载原图。用户点击“下载原图”时，前端按作品 ID 请求签名 URL 并触发下载。

### 旧作品迁移

若旧作品只有 `photoDataUrl`：

1. 将现有压缩图转为 Blob，写入 IndexedDB。
2. 上传为该作品的 `preview.jpg`。
3. 保存 `photoBackupMode = preview-only`，原图 Key 保持为空。
4. 界面显示“仅有预览图”。

若旧作品没有任何照片，则保持 `none`，不创建空 OSS 对象。

### 替换照片

1. 为新照片创建新 `photoRevision`，上传并校验两份新文件。
2. 数据库先切换到新 Object Key。
3. 数据库更新成功后，将旧版本两份 Object Key 加入清理队列并尝试删除。
4. 删除失败只会产生暂时的孤儿文件，不会导致作品照片丢失。

### 删除作品

现有删除墓碑继续负责跨设备元数据删除。云函数在应用删除补丁前读取旧记录的照片 Key，成功保存删除结果后清理 OSS 文件。若 OSS 删除失败，Key 留在清理队列，后续认证请求继续重试。离线删除仍先保存在本机同步队列，联网后执行同一流程。

## 用户界面

- 作品卡片显示：待备份、上传中、已备份、仅有预览图、失败可重试。
- 云同步区域显示照片上传和全量恢复进度。
- 登录新设备后自动启动全部预览图恢复。
- 全量恢复支持暂停、继续和重试失败项。
- 有原图的作品提供“下载原图”；旧作品没有原图时不显示该操作或显示明确说明。
- 照片上传失败不阻止作品文字保存。

## 安全设计

- Bucket ACL 为私有，并开启阻止公共访问。
- RAM 策略只允许 `twilight-cocktail-bai/photos/*` 的 `PutObject`、`GetObject` 和 `DeleteObject`。
- AccessKey Secret 不进入前端构建参数、GitHub、腾讯数据库、请求响应或日志。
- 云函数环境变量：

```text
ALIBABA_CLOUD_ACCESS_KEY_ID
ALIBABA_CLOUD_ACCESS_KEY_SECRET
ALIYUN_OSS_REGION=oss-cn-hangzhou
ALIYUN_OSS_BUCKET=twilight-cocktail-bai
ALIYUN_OSS_PREFIX=photos
```

- 签名 URL 使用 HTTPS、较短有效期、指定方法和单一对象路径。
- 云函数限制 MIME、文件大小、作品 ID、版本格式和账号路径前缀。
- 下载签名只针对数据库中已经属于当前账号的作品 Key。
- 错误日志只记录 action、错误类型和 OSS request ID，不记录账号密码校验值、签名 URL 或 AccessKey。

## 异常处理

- 无网络：作品及两份 Blob 保存在本机，进入待同步队列。
- 签名过期：重新请求签名，不复用过期 URL。
- 单文件上传失败：保留待上传 Blob，只重试未确认成功的版本。
- 数据库提交失败：保留本机同步状态并重试；已上传对象可按同一路径复用。
- 恢复单图失败：记录失败项，继续其他图片，结束后统一重试。
- IndexedDB 不可用或额度不足：保留文字数据并给出明确提示，不回退为把大量 Base64 写入 `localStorage`。
- OSS 清理失败：写入服务端清理队列，不回滚已经成功的作品删除或照片替换。
- 不支持生成预览的图片格式：不提交不完整的“双照片已备份”状态，提示用户选择浏览器可处理的图片格式；原始文件仍保留在本机待处理区。

## 测试策略

### 前端单元测试

- 原图校验、预览生成和 50 MB 上限。
- IndexedDB 缓存写入、读取、版本替换和删除。
- 上传队列状态转换和部分失败重试。
- 登录后全量预览恢复、暂停、继续、跳过已缓存版本和失败重试。
- 旧 `photoDataUrl` 向 preview-only 的兼容迁移。
- 原图下载按钮与无原图状态。

### 云函数单元测试

- 所有照片 action 必须通过现有账号密码校验。
- 对象路径只能位于当前账号前缀。
- 类型、大小、作品 ID 和版本校验。
- PUT/GET 签名请求参数正确，响应不泄露永久凭证。
- `metadata-patch` 在对象不存在或路径越权时拒绝照片元数据。
- 替换、删除和清理队列重试。
- 日志脱敏。

测试中模拟 OSS 客户端，不使用真实 AccessKey，不访问真实 Bucket。

### 集成与人工验收

- 上传普通手机原图后，OSS 中出现原图和预览图。
- 另一台电脑登录后自动恢复全部作品和全部预览图。
- 原图只在主动操作时下载。
- 断网、签名过期和单文件失败均可恢复。
- 替换照片期间旧照片始终可用。
- 删除作品后两份 OSS 文件最终被清理。
- 旧数据导入、导出和现有文字云同步不回归。
- GitHub Pages 与本地 `127.0.0.1:5173`、`localhost:5173` 均通过 CORS。

## 部署顺序

1. 实现并测试云函数 OSS 客户端、照片 actions 和元数据校验。
2. 在腾讯 CloudBase 云函数控制台配置五个环境变量，不在本地文件保存真实 Secret。
3. 部署云函数并用受控测试照片验证签名上传、下载和删除。
4. 实现前端 IndexedDB、双文件上传、状态界面和全量恢复。
5. 完成本地自动化测试和一次真实跨设备验收。
6. 最后发布 GitHub Pages；旧版本前端在迁移期内仍可读取不含照片 Key 的元数据。

## 成本与运行约束

普通手机原图一两百张预计约 0.4–2 GB；预览图只增加较小容量。OSS 新用户免费试用并非永久免费，试用期结束后存储、请求和公网流出可能按量计费。上传公网流量免费，跨电脑恢复预览图和主动下载原图会产生公网流出流量。应用因此默认全量恢复预览图，但不默认下载原图。

## 验收标准

- 新作品的原图和预览图均能安全进入私有 OSS。
- 腾讯数据库中只出现受验证的 Object Key 和照片元数据。
- 新电脑登录后无需逐页浏览即可自动恢复全部预览图。
- 全量恢复可见进度、可暂停继续、失败项可重试。
- 本地照片缓存不再依赖大量 Base64 `localStorage`。
- 旧作品可迁移预览图且不会被误标为有原图。
- 照片替换和删除不会造成当前可用照片提前丢失。
- 永久 AccessKey 不出现在前端、Git、数据库、响应或日志中。
- 现有作品文字同步、分享和其他暮调功能保持兼容。
